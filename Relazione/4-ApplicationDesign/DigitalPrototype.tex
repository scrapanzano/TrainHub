The digital prototype converted the paper structure into a consistent set of mobile screens. Figma was used to refine spacing, typography, component states, and transitions before the implementation phase. The prototype was divided into common flows, member flows, and professional flows. This organization mirrors the final navigation and avoids presenting each screen as an isolated mockup.

\paragraph{Common Flows}

Common flows are those whose interaction is shared by both roles. They establish the entry to the application and the creation of workout plans without duplicating the same design for members and professionals.

\subsubsection{Login \& Reset Password Flow}\label{subsubsect:LoginResetFlow}
% Login -> Forgot Password -> Reset Password, piu' il redirect post-login al
% ruolo corretto (/m o /p, in base al profilo). Wireframe esistenti solo in
% doc/assets/pt/01-03 (Login, Forgot Password, Set Password) -- condivisi tra
% i due ruoli, nessun set separato lato cliente. Diagramma mermaid lineare,
% con un ramo per "password dimenticata" e uno per il login diretto.

The authentication flow begins with a shared login screen. A successful login opens the correct role area according to the profile returned by Supabase. The secondary path leads from \textit{Forgot Password} to the reset screen opened from the recovery email. Keeping these screens outside both role trees avoids duplicating authentication logic and provides a consistent entry point.

\subsubsection{Plan Creation \& Editing Flow}\label{subsubsect:PlanCreationEditingFlow}
% CreatePlanFlow.jsx e' condiviso testualmente tra i due ruoli ("Used by both
% roles. Only memberId, authorId and onDone differ.") -- un solo flusso, non
% duplicato. Ramo principale: 2 step in-pagina (nome piano -> prima sessione
% con esercizi aggiunti via autocomplete inline), nessuna schermata di
% riepilogo -- torna dritto alla panoramica del piano. Entry point diverso
% per ruolo: tab Workout per il cliente, Client Detail per il professionista
% -- da annotare nel diagramma, non da raccontare due volte.
%
% Ramo secondario, editing di un piano gia' esistente (aggiungere una
% sessione o un esercizio): stesso SessionForm, ma interfaccia diversa per
% ruolo -- lato cliente sono due schermate a parte (Add a Session, Add an
% Exercise), lato professionista e' tutto inline dentro Client Detail /
% Workout Plan (nessuna navigazione). Il diagramma deve mostrare questa
% divergenza, non solo il ramo comune.

Workout-plan creation follows the same conceptual flow for both roles. The user first enters the plan information, then drafts one or more sessions and their prescribed exercises, and finally reviews the complete plan in a summary. Sessions can be added, reopened, corrected, or removed before confirmation. The difference is the entry point: a member starts from the Workout area and creates a personal plan, while a professional starts from a client's profile and assigns the plan to that client. Nothing is written to the database until the final confirmation, when the plan and every drafted session are saved as one unit.

Editing an existing plan results in a replacement version rather than destructive changes to the history already used by completed workouts. On the member side this action starts from the plan overview. On the professional side it remains within the selected client's workout area. In both cases, the latest version becomes the active plan after a successful save.

\subsubsection{Notification Centre Flow}\label{subsubsect:NotificationCentreFlow}

The notification icon opens a dedicated screen shared by members and professionals. The list brings together messages, appointment updates, workout plans, and nutrition plans rather than treating the bell as a shortcut to chat. Unread items are visually distinguished and each row leads to the screen that generated it. An item becomes read when its destination is visited, regardless of whether the user arrived from the list, an operating-system push notification, or another part of the application.

The screen supports All and Unread filters, individual deletion, and a selection mode for marking or deleting several entries. Select-all and destructive confirmations make bulk actions explicit. The badge in the header is updated through Supabase Realtime, with periodic refresh retained as a fallback if the live channel is unavailable.

\paragraph{Client Flows}

The member prototype gives priority to actions performed frequently and in short intervals, particularly reading the daily plan and recording a set during training.

\subsubsection{Home \& Global Navigation Flow}\label{subsubsect:ClientHomeNavFlow}
% Home come screenshot d'apertura della sezione Cliente. Frecce etichettate
% "tab bar" verso Workout, Nutrition, My Trainer; freccia etichettata
% "avatar" verso Profile. Sono i punti d'accesso sempre raggiunti dalla shell
% dell'app (bottom nav + top bar), non link dentro il contenuto della Home --
% da leggere come premessa visiva ai flussi seguenti, non come schermata con
% link propri.

The member Home screen combines the current week, the next workout, nutrition information, appointments, and quick access to the main services. The bottom bar keeps Workout, Nutrition, and My Trainer available throughout the application, while the avatar opens Profile. The header also provides access to the shared notification centre and displays the current unread count.

\subsubsection{Workout Plan Exploration Flow}\label{subsubsect:WorkoutExplorationFlow}
% Workout Plan -> Session Detail -> Exercise Detail, senza avviare una
% sessione live. Percorso di sola consultazione.

The workout overview presents the active plan and its weekly completion state. Selecting a session opens the exercise list, and selecting an exercise opens its prescription, including sets, repetitions, weight, rest time, and performance notes. This consultation path does not start a workout and can therefore be used to prepare before entering the gym.

\subsubsection{Live Session Flow}\label{subsubsect:LiveSessionFlow}
% Session Detail -> Live Session -> Exercise Detail Live (stato inline dentro
% Live Session, non una route separata) -> Open-Run Sheet / End-Run Sheet
% (overlay) -> Congratulations Dialog (overlay) -> Session Summary. Diagramma
% mermaid con frecce per le diramazioni: Open-Run Sheet quando un secondo run
% si apre mentre uno e' gia' attivo, "Stopped Early" quando si esce da
% End-Run Sheet senza completare.

From the session detail, the play action opens a live workout run. The member logs each set directly from the exercise detail, can start a rest timer, and may pause or resume the workout. A mini-player remains above the bottom navigation when the member leaves the live screen. Ending the run opens a confirmation sheet and then a summary with duration, logged sets, completion percentage, points, and an optional note for the professional.

\subsubsection{Nutrition Flow}\label{subsubsect:NutritionFlow}
% Nutrition Plan -> Meal Detail (route /m/nutrition/meal/:mealId gia'
% esistente, wireframe ancora da fare -- nodo comunque presente, non
% taciuto). Ramo stato vuoto (nessun piano assegnato) -> Book Appointment,
% che rimanda al Personal Trainer \& Booking Flow.

The Nutrition area displays the plan assigned by a qualified professional. The week selector is connected to the plan's day types: selecting a date shows the template assigned to that weekday and the meals ordered within it. Opening a meal reveals its foods, quantities, calories, macronutrients, and possible alternatives. When no plan is assigned, or no day type covers the selected weekday, the interface presents a specific empty state instead of an unexplained blank page.

\subsubsection{Personal Trainer \& Booking Flow}\label{subsubsect:TrainerBookingFlow}
% My Trainer -> Chat; My Trainer -> View Appointments -> Booking Sheet ->
% conferma prenotazione. Ramo "nessun professionista assegnato" -> Browse
% Trainers (redirect automatico da My Trainer quando non c'e' ancora un
% professionista scelto).

My Trainer presents the assigned professional and the two most frequent actions: opening the conversation and viewing appointments. The appointment view opens a booking sheet without leaving the selected date. If no professional is assigned, the member is directed to Browse Trainers, where profiles can be filtered by specialty and selected before chat or booking becomes available.

\subsubsection{Profile Flow}\label{subsubsect:ClientProfileFlow}
% Profile -> Access Badge, Subscription, Rewards, Settings. Diagramma a
% stella: tutti i rami partono da Profile, nessun collegamento tra loro.

The member profile acts as a hub for less frequent personal actions. Separate rows lead to the rotating access badge, subscription information, earned rewards, and settings. These destinations are intentionally outside the bottom navigation because they are not part of the member's primary daily workflow. When the membership is suspended or expired, a persistent shell banner explains which services are paused and the affected screens repeat the reason next to their unavailable action.

\paragraph{Professional Flows}

The professional prototype focuses on overview and comparison. Its home and client screens summarize information first, while detailed editing remains available after selecting the relevant client or appointment.

\subsubsection{Home \& Global Navigation Flow}\label{subsubsect:ProHomeNavFlow}
% Stessa struttura del flusso Home lato cliente: Home come screenshot
% d'apertura, frecce "tab bar" verso Clients, Calendar, Chat; freccia
% "avatar" verso Profile. L'agenda mostrata in Home include anche
% un'anteprima appuntamenti che rimanda al Calendar Flow -- non ripetuta qui,
% solo richiamata.

The professional Home screen is centered on the daily agenda and quick access to client management. The bottom bar links Home, Clients, Calendar, and Chat. The top bar provides the profile entry point, notification indicator, and access to the QR scanner. This arrangement keeps time-sensitive tasks visible while separating settings from daily work.

\subsubsection{Calendar Flow}\label{subsubsect:CalendarFlow}
% Calendar -> Availability. Calendar -> Appointment Detail (raggiungibile
% anche dall'anteprima appuntamenti in Home). Nuovo appuntamento ("+") come
% azione inline sulla stessa schermata di Calendar, non una route a parte.

The Calendar screen combines a monthly overview with appointments for the selected day. A professional can create a new appointment in context, open an existing appointment to update its status, and configure recurring availability from the same section. Appointment cards use different visual accents for training, protocol, and nutrition services.

\subsubsection{Client Management Flow}\label{subsubsect:ClientManagementFlow}
% Clients -> Client Detail -> quattro rami: Chat (stesso nodo Chat della tab
% bar -- doppia via d'accesso, un solo screenshot di destinazione); Workout
% Plan (rimanda al Plan Creation \& Editing Flow comune, meccanismo identico
% a quello del cliente); Nutrition Plan (consultazione + creazione/editing
% inline -- ramo professionista-only, il cliente non ha mai un bottone "+"
% qui); Progress Tracking (sola consultazione, nessuna creazione).

The Clients screen lists the people assigned to the signed-in professional and highlights useful subscription and activity information. Opening a client reveals four related areas: chat, workout plan, nutrition plan, and progress. The same profile provides a contextual action to suspend or reactivate the membership. Workout and nutrition plans use read-only summaries once created and are changed by building a replacement version; their creation actions are unavailable while the selected membership is inactive. The progress section combines weekly training, run details, notes, and body measurements.

\subsubsection{Profile \& Settings Flow}\label{subsubsect:ProProfileSettingsFlow}
% Profile -> Settings. Molto piu' corto della versione cliente: nessun badge,
% subscription o rewards lato professionista.

The professional profile is intentionally shorter than the member version. It provides account information and access to settings, including push-notification preferences and sign-out. Membership, rewards, and the personal access badge do not apply to this role and are therefore omitted.
