\subsection{Digital Prototype}\label{subsect:DigitalPrototype}

The digital prototype converted the paper structure into a consistent set of mobile screens. Figma was used to refine spacing, typography, component states, and transitions before the implementation phase. The prototype was divided into common flows, member flows, and professional flows. This organization mirrors the final navigation and avoids presenting each screen as an isolated mockup.

\subsubsection{Common Flows}\label{subsubsect:CommonFlows}

Common flows are those whose interaction is shared by both roles. They establish the entry to the application and the creation of workout plans without duplicating the same design for members and professionals.

\paragraph{Login \& Reset Password Flow}\label{subsubsect:LoginResetFlow}

The authentication flow begins with a shared login screen (Figure \ref{fig:digitalLoginFlow}). A successful login opens the correct role area according to the profile returned by Supabase. The secondary path leads from \textit{Forgot Password} to the reset screen opened from the recovery email. Keeping these screens outside both role trees avoids duplicating authentication logic and provides a consistent entry point.

    \includegraphics[width=0.62\textwidth]{\detokenize{4-ApplicationDesign/img/DititalPrototype/Member/Login&ResetPasswordFlow.jpg}}
    \caption{Login, password recovery, and the screen opened from the recovery email.}
    \label{fig:digitalLoginFlow}
\end{figure}

\paragraph{Plan Creation \& Editing Flow}\label{subsubsect:PlanCreationEditingFlow}

Workout-plan creation follows the same conceptual flow for both roles (Figure \ref{fig:digitalPlanCreation}). The user first enters the plan information, then drafts one or more sessions and their prescribed exercises, and finally reviews the complete plan in a summary. Sessions can be added, reopened, corrected, or removed before confirmation. The difference is the entry point: a member starts from the Workout area and creates a personal plan, while a professional starts from a client's profile and assigns the plan to that client. Nothing is written to the database until the final confirmation, when the plan and every drafted session are saved as one unit.

Editing an existing plan results in a replacement version rather than destructive changes to the history already used by completed workouts. On the member side this action starts from the plan overview. On the professional side it remains within the selected client's workout area. In both cases, the latest version becomes the active plan after a successful save.

    \caption{Plan information, session drafting, and the summary confirmed before saving.}
    \label{fig:digitalPlanCreation}
\end{figure}

\paragraph{Notification Centre Flow}\label{subsubsect:NotificationCentreFlow}

The notification icon opens a dedicated screen shared by members and professionals. The list brings together messages, appointment updates, workout plans, and nutrition plans. Unread items are visually distinguished and each row leads to the screen that generated it. An item becomes read when its destination is visited, regardless of whether the user arrived from the list, an operating-system push notification, or another part of the application.

The screen supports All and Unread filters, individual deletion, and a selection mode for marking or deleting several entries. Select-all and destructive confirmations make bulk actions explicit. The badge in the header is updated through Supabase Realtime, with periodic refresh retained as a fallback if the live channel is unavailable.

\subsubsection{Client Flows}\label{subsubsect:ClientFlows}

The member prototype gives priority to actions performed frequently and in short intervals, particularly reading the daily plan and recording a set during training.

\paragraph{Home \& Global Navigation Flow}\label{subsubsect:ClientHomeNavFlow}

The member Home screen answers one question: what happens today. It lists the activities booked for the day and the session waiting to be trained, and leaves everything else to the navigation. The bottom bar keeps Workout, Nutrition, and My Trainer available throughout the application, while the avatar opens Profile. The header also provides access to the shared notification centre and displays the current unread count. Figure \ref{fig:digitalMemberHome} shows the five destinations a member can reach from any screen.

\paragraph{Workout Plan Exploration Flow}\label{subsubsect:WorkoutExplorationFlow}

The workout overview presents the active plan and its weekly completion state (Figure \ref{fig:digitalWorkoutExploration}). Selecting a session opens the exercise list, and selecting an exercise opens its prescription, including sets, repetitions, weight, rest time, and performance notes. This consultation path does not start a workout and can therefore be used to prepare before entering the gym.

\paragraph{Live Session Flow}\label{subsubsect:LiveSessionFlow}

From the session detail, the play action opens a live workout run (Figure \ref{fig:digitalLiveSession}). The member logs each set directly from the exercise detail, can start a rest timer, and may pause or resume the workout. A mini-player remains above the bottom navigation when the member leaves the live screen. Ending the run opens a confirmation sheet and then a summary with duration, logged sets, completion percentage, points, and an optional note for the professional.

\paragraph{Nutrition Flow}\label{subsubsect:NutritionFlow}

The Nutrition area displays the plan assigned by a qualified professional (Figure \ref{fig:digitalNutrition}). A strip of the current week sits under the header and is connected to the plan's day types: selecting a date shows the template assigned to that weekday and the meals ordered within it. Opening a meal reveals its foods, quantities, calories, macronutrients, and possible alternatives. When no plan is assigned, or no day type covers the selected weekday, the interface presents a specific empty state instead of an unexplained blank page.

If no professional is assigned, the member is directed to Browse Trainers, where profiles can be filtered by specialty and selected before chat or booking becomes available.

\subsubsection{Professional Flows}\label{subsubsect:ProfessionalFlows}

The professional prototype focuses on overview and comparison. Its home and client screens summarize information first, while detailed editing remains available after selecting the relevant client or appointment.

\paragraph{Home \& Global Navigation Flow}\label{subsubsect:ProHomeNavFlow}

The professional Home screen is centered on the daily agenda (Figure \ref{fig:digitalProHome}). The bottom bar links Home, Clients, Calendar, and Chat. The top bar provides the profile entry point, notification indicator, and access to the QR scanner. This arrangement keeps time-sensitive tasks visible while separating settings from daily work.

\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{\detokenize{4-ApplicationDesign/img/DititalPrototype/Professional/Home&GlobalNavigationFlow.jpg}}
    \caption{The professional's top-level destinations: Home, Clients, Calendar, Chat, and Profile.}
    \label{fig:digitalProHome}
\end{figure}

\paragraph{Calendar Flow}\label{subsubsect:CalendarFlow}

The Calendar screen combines a monthly overview with appointments for the selected day. A professional can create a new appointment in context, open an existing appointment to update its status, and configure recurring availability from the same section. Appointment cards use different visual accents for training, protocol, and nutrition services.

\paragraph{Client Management Flow}\label{subsubsect:ClientManagementFlow}

The Clients screen lists the people assigned to the signed-in professional and highlights useful subscription and activity information (Figure \ref{fig:digitalClientManagement}). Opening a client reveals four related areas: chat, workout plan, nutrition plan, and progress. The same profile provides a contextual action to suspend or reactivate the membership. Workout and nutrition plans use read-only summaries once created and are changed by building a replacement version; their creation actions are unavailable while the selected membership is inactive. The progress section combines the weekly training summary, the detail of a single run, and the note the member writes when closing it.

    \caption{From the client list to the client profile, the assigned nutrition plan, and progress.}

\paragraph{Nutrition Plan Creation Flow}\label{subsubsect:NutritionPlanCreationFlow}

Creating a nutrition plan is reserved for professionals, and only for the clients assigned to them: a member can author a workout plan but never a diet. The flow starts from the client's nutrition area and follows the same two-step shape as workout-plan creation (Figure \ref{fig:digitalNutritionPlanCreation}). The first step records the plan itself, with its name, daily calorie target, macronutrient split, and any note for the client. The second step builds the week out of reusable day types: each day type is given a name, assigned to one or more weekdays, and filled with meals carrying a time, calories, macronutrients, alternatives, and the individual food items.

A weekday can belong to only one day type, so the chips already taken are disabled while a second day is being written. As in the workout wizard, the draft lives on the device until it is confirmed, and the plan, its day types, and every meal are then written together.

\paragraph{Profile \& Settings Flow}\label{subsubsect:ProProfileSettingsFlow}

The professional profile is intentionally shorter than the member version. It provides account information and access to settings, including push-notification preferences and sign-out. Membership, rewards, and the personal access badge do not apply to this role and are therefore omitted.
